# 多挖掘点规划（TODO）

这个目录用于记录“多挖掘点连续作业”的规划设计与实现任务列表。当前仿真链路已经
可以在 RViz 中完成单点“挖掘 -> 卸料”的完整流程，但真实作业通常需要在多个挖掘点
之间循环执行，并在所有点完成后再归位。

本目录把多点实现分为两种模式：

- 模式 1：给定挖掘区域（矩形框），并设置左旋或右旋 `X°` 的卸料区域
- 模式 2：由点云交互给出一组需要连续挖掘的点，由程序进行筛选、排序和分层

## 目录结构约定

多点规划相关内容统一放在 `v14_urdf` 下，按模式分目录，避免和历史版本耦合：

- `v14_urdf/mode1/`：模式 1（区域采样）实现与说明
- `v14_urdf/mode2/`：模式 2（手动点集）实现与说明（后续创建）

## 通用约束（两种模式都适用）

多点挖掘任务必须满足以下共性约束，否则会出现不可达或动作不稳定：

- **坐标系一致**
  - 输入点必须表达在“回转中心地面投影点”为原点的工作坐标系中。
- **工作空间裁剪**
  - 任何候选挖掘点都必须先经过可达性过滤（半径、回转扇区、高度范围）。
- **初始化与归位不参与循环**
  - 初始化只执行一次。
  - 归位只执行一次。
  - 循环内部只包含“挖掘 -> 卸料 -> 循环过渡位”。
- **循环内部有公共过渡位**
  - 每次卸料后回到一个 `cycle_transit_pose`，然后再前往下一个挖掘点。
  - 避免每轮都回到初始位导致动作冗余。
- **关节语义固定**
  - `bucket_arm = 0`：铲斗接近闭合
  - `bucket_arm ≈ -90`：铲斗接近完全打开

## 模式 1：区域采样（优先实现）

模式 1 的核心是把“几何挖掘区域”转换为“有顺序的挖掘点序列”，然后复用单点规划器
生成每次循环的动作段，再拼接成完整任务。

你需要定义三类输入：

- **挖掘区域矩形框**
  - 中心点 `(cx, cy, cz)`
  - 长度 `length`
  - 宽度 `width`
  - 朝向 `yaw`（矩形框自身朝向）
- **卸料区域（回转偏角）**
  - 方向：`left` 或 `right`
  - 偏角：`X°`
  - 可选容差：`± tolerance_deg`
  - 卸料半径：`dump_radius`
  - 卸料高度：`dump_height`
- **工作空间边界**
  - `r_min` / `r_max`
  - `yaw_min` / `yaw_max`
  - `z_min` / `z_max`

模式 1 的最小交付物：

- 输入配置：一个 JSON 文件描述矩形框、卸料策略、工作空间
- 输出任务：一个任务级 JSON 文件，包含：
  - `init_segment`
  - `cycle_segment[]`（每个挖掘点一段）
  - `home_segment`
- RViz 验证方式：用 `/joint_states` 回放整段任务，确认循环次数、卸料方向和归位正确

详细设计与实现计划见：

- [mode1/README.md](file:///media/libo/libo_sn7100/ubuntu2204/shandong_ws/src/shandong/v14_urdf/mode1/README.md)

## 模式 2：手动点集（后续实现）

模式 2 的核心是把“你在点云界面里选择的一组点”转换为“适合执行的点序列”。这里最
容易出问题的是点的顺序、密度、深度层混叠，以及不可达点混入。

建议你在给点时按以下规则组织：

- 每次只给同一层（深度相近）的一批点，建议 `3` 到 `8` 个
- 相邻点间距建议 `0.08 m` 到 `0.20 m`
- 相邻点高度差建议不超过 `0.05 m`
- 同一批点的回转角变化建议不超过 `15°` 到 `20°`
- 点的列表顺序建议与期望执行顺序一致

程序侧需要的预处理步骤：

1. 可达性过滤（工作空间裁剪）
2. 去重与稀疏化（避免点过密导致频繁微调）
3. 排序（按条带或最近邻，减少大幅度回转/伸缩）
4. 分层（可选，用于多层切削）

模式 2 的实现建议后续在 `v14_urdf/mode2/README.md` 补齐。
